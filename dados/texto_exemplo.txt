Estruturas de Dados e a Arte de Organizar Informação

Todo programa de computador manipula dados. Uma calculadora guarda números, um editor de texto guarda letras, um jogo guarda a posição dos personagens e um aplicativo de mapas guarda cidades, ruas e distâncias. A forma como esses dados são organizados na memória determina o quanto o programa será rápido, simples e confiável. É por isso que o estudo de estruturas de dados ocupa um lugar central na formação de qualquer profissional de computação.

Uma estrutura de dados é uma maneira de armazenar e organizar dados para que certas operações sejam eficientes. Não existe uma estrutura perfeita para todos os problemas. Cada estrutura oferece vantagens para algumas operações e desvantagens para outras. Um vetor permite acessar qualquer posição de forma imediata, mas inserir um elemento no meio exige deslocar muitos outros. Uma lista encadeada facilita inserções, porém obriga o programa a percorrer os elementos um a um para encontrar um dado. Escolher a estrutura certa é, portanto, escolher quais operações serão rápidas.

Entre as estruturas mais úteis está a tabela hash. A ideia da tabela hash é transformar uma chave, como uma palavra ou um número de matrícula, em uma posição dentro de um vetor. Essa transformação é feita por uma função hash. Quando a função hash é boa, as chaves se espalham de maneira uniforme pelas posições do vetor e cada busca leva, em média, tempo constante. Isso significa que procurar uma chave em uma tabela com dez elementos ou com dez milhões de elementos custa praticamente o mesmo tempo.

Naturalmente, duas chaves diferentes podem gerar a mesma posição. Esse evento é chamado de colisão. As colisões são tratadas por técnicas como o encadeamento, em que cada posição guarda uma pequena lista de chaves, ou o endereçamento aberto, em que o programa procura outra posição livre no vetor. Quando a tabela fica muito cheia, ela é redimensionada e as chaves são redistribuídas. Por causa das colisões, o pior caso de uma busca pode ser linear, mas na prática o custo médio permanece constante.

A linguagem Python oferece o dicionário como uma tabela hash pronta. Com um dicionário, contar a frequência de palavras em um texto se torna uma tarefa simples: para cada palavra, o programa verifica se a chave já existe e incrementa o seu contador. Como a busca, a inserção e a atualização custam tempo constante em média, a contagem de um texto inteiro custa tempo proporcional ao número de palavras. Sem uma tabela hash, seria preciso comparar cada nova palavra com todas as palavras já vistas, e o custo cresceria de forma quadrática.

Outra estrutura fundamental é o grafo. Um grafo é formado por vértices, também chamados de nós, e por arestas, que ligam pares de vértices. Grafos modelam redes de todo tipo: cidades ligadas por estradas, computadores ligados por cabos, pessoas ligadas por amizades e páginas ligadas por links. Quando as arestas possuem pesos, como distâncias, tempos ou custos, o grafo é chamado de grafo ponderado.

Um grafo pode ser representado por uma matriz de adjacência ou por uma lista de adjacência. A matriz guarda uma linha e uma coluna para cada vértice e ocupa espaço proporcional ao quadrado do número de vértices. A lista de adjacência guarda, para cada vértice, apenas os seus vizinhos e os pesos das arestas. Em grafos com poucas arestas, a lista de adjacência economiza memória e permite percorrer os vizinhos de um vértice de forma direta. Curiosamente, a lista de adjacência costuma ser implementada com uma tabela hash, que associa cada vértice à sua lista de vizinhos.

Um dos problemas mais conhecidos em grafos é o problema do caminho mínimo. Dado um vértice de origem e um vértice de destino, deseja-se encontrar o caminho cuja soma dos pesos seja a menor possível. O algoritmo de Dijkstra resolve esse problema para grafos com pesos não negativos. O algoritmo mantém uma estimativa de distância para cada vértice, começa pela origem com distância zero e, a cada passo, escolhe o vértice ainda não visitado com a menor distância conhecida. Em seguida, ele tenta melhorar a distância dos vizinhos desse vértice, em um processo chamado de relaxamento.

Para escolher rapidamente o vértice de menor distância, o algoritmo de Dijkstra utiliza uma fila de prioridade, normalmente implementada com um heap. Com essa combinação, o algoritmo executa em tempo proporcional ao número de arestas multiplicado pelo logaritmo do número de vértices. Ao final, guardando o vértice anterior de cada vértice no caminho, é possível reconstruir a rota completa da origem até o destino.

É importante perceber que o menor caminho nem sempre é o caminho com menos arestas. Uma rota com três estradas curtas pode ser mais curta do que uma rota com duas estradas longas. O algoritmo de Dijkstra considera os pesos das arestas, e não apenas a quantidade de conexões, e por isso encontra a rota de menor distância total. Quando não existe nenhum caminho entre a origem e o destino, a distância permanece infinita e o programa deve informar essa situação ao usuário.

Tabelas hash e grafos mostram que a escolha da estrutura de dados não é um detalhe de implementação. Ela define a eficiência da solução. Um bom programador entende o problema, escolhe a estrutura adequada, conhece o custo de cada operação e sabe justificar as suas decisões. Estudar estruturas de dados é aprender a pensar sobre dados, e pensar bem sobre dados é o primeiro passo para escrever programas melhores.
